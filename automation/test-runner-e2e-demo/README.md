# TestRun end-to-end demo

Отдельный Java-проект для демонстрации сквозного сценария TestRun. Он не меняет приложение и не использует production-учётную запись автоматически.

## Стек

- Java 17+
- Selenium WebDriver 4 (ChromeDriver через Selenium Manager)
- JUnit 5
- Allure Report

## Безопасная подготовка

1. Используйте только отдельный тестовый сервер TestRun и отдельного demo-пользователя.
2. Не указывайте адрес production, если не хотите создавать там демонстрационные проекты и прогоны.
3. Создайте отдельную учётную запись для автоматизации и задайте её данные только в переменных окружения.
4. Убедитесь, что Chrome установлен на машине, где запускаются тесты.

## Переменные окружения (PowerShell)

```powershell
$env:TESTRUN_BASE_URL = "http://127.0.0.1:15052"
$env:TESTRUN_DEMO_EMAIL = "demo@example.test"
$env:TESTRUN_DEMO_PASSWORD = "значение-пароля"
$env:TESTRUN_HEADLESS = "false"
$env:TESTRUN_E2E_ENABLED = "true"
```

Пароль не записывайте в файлы проекта, Git или отчёт Allure. В примере выше замените адрес и учётные данные на значения из изолированной тестовой среды.

## Запуск

Из каталога проекта:

```powershell
gradle test
gradle allureReport
```

Отчёт Allure: `build/reports/allure-report/allureReport/index.html` (точный каталог зависит от версии Gradle Allure plugin).

Сквозной UI-тест намеренно пропускается, пока явно не задано `TESTRUN_E2E_ENABLED=true`. Это защита от случайного создания проектов и прогонов в неподходящей среде. API-тест также включается только при заданных API-переменных.

Для запуска в фоне без окна браузера задайте:

```powershell
$env:TESTRUN_HEADLESS = "true"
```

## Что проверяет основной сценарий

1. Вход отдельным demo-пользователем.
2. Создание уникального демонстрационного проекта.
3. Создание тест-кейса с предусловием, шагом и параметрами.
4. Проверка сохранения параметров на странице тест-кейса.
5. Запуск тест-кейса, фиксация статусов и комментария шага.
6. Проверка истории и скачиваемого PDF-отчёта.
7. Проверка переходов к проекту и панели.

Тест намеренно не удаляет созданный проект: его можно использовать для демонстрации истории. Для каждого запуска создаётся новое имя с временной меткой.

## Отдельная проверка API

Класс `TestRunApiIntegrationTest` запускается только если дополнительно заданы:

- `TESTRUN_API_TOKEN` — отдельный API-токен demo-пользователя;
- `TESTRUN_TEST_CASE_ID` — ID существующего тест-кейса в тестовой среде;
- `TESTRUN_DATA_SET_ID` — ID набора данных этого тест-кейса.

Токен должен иметь обычные права чтения/записи результатов. Для этого теста не требуется разрешение на получение секретных значений: API проверяется без запроса секретов. Токен храните только в переменной окружения.

## Ограничения

- Это демонстрационный UI/API smoke-test, а не тест внешнего сайта: Selenium управляет интерфейсом TestRun.
- Проверка ИИ вынесена отдельно и не запускается этим сценарием. Она будет добавлена после завершения настройки AI-провайдера и только как необязательный тест.
- Не запускайте одновременно несколько копий этого сценария под одной demo-учётной записью.
