## Начало работы

TestRun доступен в браузере: [https://testrun.pro](https://testrun.pro). Для работы нужен современный браузер и подключение к интернету.

## Регистрация и вход

1. Откройте сайт.
2. Нажмите «Зарегистрироваться».
3. Укажите email и пароль.
4. Для входа используйте зарегистрированные email и пароль.

## Интерфейс

В боковом меню доступны Dashboard, проекты, личный кабинет, поддержка, документация, API-токены и переключатель темы. Администрирование доступно только уполномоченному аккаунту.

## Личный кабинет

В кабинете можно посмотреть данные аккаунта, название компании, статистику прогонов, свои проекты и последние обращения в поддержку.

## Проекты

Создайте проект в разделе «Проекты», задав ему название. Внутри проекта находятся тест-кейсы и связанные результаты. Удаление проекта является разрушительной операцией: вместе с ним удаляются связанные тесты и результаты. Перед удалением убедитесь, что данные больше не нужны.

## Тест-кейсы

Тест-кейс содержит название, предусловие и список шагов. Для каждого шага указываются действие и ожидаемый результат. При изменении содержания сохраняется версия тест-кейса; история версий позволяет просматривать предыдущие варианты.

## Параметризация тест-кейсов

Параметризация позволяет использовать один тест-кейс с разными входными данными, не создавая копию теста для каждого пользователя или сценария.

### 1. Добавьте переменные в текст тест-кейса

В предусловии, шагах или ожидаемых результатах используйте имена в двойных фигурных скобках, например:

- `{{base_url}}` — адрес тестового стенда;
- `{{login}}` — имя пользователя;
- `{{password}}` — пароль;
- `{{expected_message}}` — ожидаемый текст.

Имена переменных должны соответствовать ключам колонок набора данных.

### 2. Создайте набор данных

Откройте управление тестовыми данными из карточки тест-кейса. Создайте набор, добавьте колонки и строки. Каждая строка — отдельный пример данных, с которым можно выполнить тот же тест-кейс.

Для каждой колонки задаётся ключ переменной и понятная подпись. Строки можно редактировать, включать и отключать. Неактивные строки не участвуют в новом последовательном запуске.

### 3. Отметьте секретные колонки

Пароли, токены и другие чувствительные значения нужно хранить в колонках, отмеченных как «Секрет». Секретные значения шифруются на сервере и не подставляются обратно в обычную форму редактирования. Пустое поле при редактировании сохраняет прежнее значение; для удаления секрета используется отдельное действие очистки.

Не помещайте пароли и токены в обычные колонки, комментарии, названия строк или текст шагов.

### 4. Запустите тест

Можно запустить тест с одной выбранной строкой или последовательно обработать активные строки набора. Каждая итерация создаёт отдельную запись истории. Состав последовательного запуска фиксируется в момент его старта: последующее отключение строки не меняет уже начатый запуск.

Если строку удалили до перехода к ней, последовательный запуск корректно прекращается. Повторная отправка одной и той же итерации не должна создавать дубликат результата.

### 5. Посмотрите историю

В истории отображаются результаты и подписи набора/строки. Исторические снимки нужны для того, чтобы изменение или удаление текущего набора не переписывало данные уже выполненных прогонов. Секретные значения не должны отображаться в истории или PDF.

> Доступность параметризации в рабочем сервисе зависит от выпуска соответствующей версии. Перед использованием на production функция должна пройти ручную приёмку и миграцию отдельной тестовой базы.

## Прогон тестов

Для обычного ручного прогона откройте тест-кейс и нажмите «Запустить». Для каждого шага выберите статус:

- **PASS / Пройден** — ожидаемый результат достигнут;
- **FAIL / Не пройден** — обнаружено отклонение;
- **SKIP / Пропущен** — шаг не выполнялся.

При необходимости добавьте комментарий и сохраните результат.

## Отчёты и история

История проекта показывает предыдущие прогоны, шаги и комментарии. На странице статистики можно экспортировать PDF за выбранный период. PDF поддерживает кириллицу. Для параметризованных прогонов в отчёте могут отображаться подписи набора и строки, но не секретные значения.

## Поддержка и Dashboard

Dashboard показывает сводную статистику по результатам. В разделе поддержки пользователь создаёт обращение и продолжает переписку внутри него. Пользователь видит только собственные обращения; администратор обрабатывает обращения пользователей.

## Автоматизация через API

TestRun предоставляет API для интеграции с Selenium, Selenide, JUnit 5 и другими системами автоматизации.

- API-токен передаётся в заголовке `Authorization: Bearer ...` или `X-API-Token`.
- Для параметризованных автотестов доступны методы получения наборов и активных строк.
- `POST /api/run` сохраняет результат автотеста; необязательные `data_set_id` и `data_row_id` связывают его с использованной строкой.
- Секретные значения по умолчанию не выдаются. Для их получения одновременно нужны специальное разрешение токена и явный заголовок opt-in.

Подробный контракт и пример Java 17 + JUnit 5 + Selenide: [automation-test-data-api.md](automation-test-data-api.md). Правила работы с ключом шифрования: [encrypted-test-data-secrets.md](encrypted-test-data-secrets.md).

## Темы и администрирование

Светлая/тёмная тема переключается в боковом меню. Администратор может просматривать пользователей, применять блокировки и обрабатывать обращения. Ветка администрирования и конкретный набор доступных операций должны быть проверены перед выпуском соответствующего обновления.
