# Русскоязычный интерфейс параметров тест-кейса

## Цель

Сделать параметры и варианты тестовых данных естественной частью работы с тест-кейсом. Пользователь должен видеть параметры рядом с шагами, а управление набором не должно требовать постоянного перехода между множеством отдельных форм.

## Принципы интерфейса

- Все подписи, подсказки, статусы и подтверждения — на русском языке.
- Название параметра можно задавать кириллицей, например `Исполнитель 1` или `Текст поручения`.
- Синтаксис подстановки в предусловиях и шагах: `{{Исполнитель 1}}`.
- При создании параметра достаточно указать его имя. Отображаемая подпись по умолчанию совпадает с именем; расширенное редактирование подписи остаётся доступным.
- В редакторе тест-кейса есть список параметров, которые можно вставить в поле предусловия, действия или ожидаемого результата нажатием кнопки.
- На странице тест-кейса показывается краткая таблица параметров и значения первого активного варианта.
- Редактирование структуры параметров и значений вариантов сворачивается, чтобы не перегружать экран.
- Наборы можно переименовывать. Переименование не меняет исторические снимки запусков.
- Секретные значения никогда не показываются в сводной таблице и остаются в существующем зашифрованном хранилище.
- Можно запустить один вариант или все активные варианты набора.

## Требования к совместимости

- Не менять существующую модель наборов, параметров, вариантов, пакетных запусков и снимков истории без отдельной необходимости.
- Не хранить секретные значения в открытом JSON.
- Не менять уже сохранённые исторические результаты при переименовании или редактировании текущего набора.
- Сохранять совместимость старых тест-кейсов и API.
- Не выполнять изменения в рабочей базе или production при разработке интерфейса.

## Связь с ИИ-помощником

При дальнейшей интеграции AI-генерации необходимо расширить черновик тест-кейса необязательным блоком предлагаемых параметров и одного или нескольких вариантов данных.

- ИИ может предложить параметр, только если его необходимость следует из требования.
- ИИ не должен выдумывать логины, пароли, токены, реальные URL, пользователей или бизнес-значения. Неизвестные значения отмечаются как вопросы/допущения.
- Секретные поля должны быть явно помечены и не должны заполняться вымышленными секретами.
- Сгенерированные параметры и значения остаются черновиком до просмотра и явного подтверждения пользователя.
- Сохранение черновика должно создавать обычный тест-кейс и связанные с ним наборы/варианты согласованно, без частичной записи.
- Для платного провайдера сохраняется существующее отдельное подтверждение запроса и оплаты. Локальный режим разработки остаётся доступным отдельно.

## Критерии приёмки

- Пользователь может создать набор с русскими названиями параметров без повторного ввода того же имени в поле подписи.
- Пользователь может вставить параметр в предусловие, действие и ожидаемый результат.
- Сводка тест-кейса показывает значения обычных параметров, но скрывает секреты.
- Пользователь может переименовать набор и отредактировать вариант без изменения истории.
- Пользователь может запустить отдельный или все активные варианты.
- Автоматические тесты покрывают русские имена, права доступа, валидацию, сохранение истории и шифрование.
- AI-черновик можно проверить и изменить до сохранения; AI не обходит существующие ограничения стоимости и безопасности.
